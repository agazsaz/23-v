# Лабораторная работа: Подключение к Raspberry Pi по протоколу SSH

## Цель работы
Научиться подключаться к Raspberry Pi по SSH, выполнять базовые команды для работы с файловой системой, а также настроить аутентификацию по SSH-ключам для беспарольного доступа.

## Часть 1. Подключение и работа с файлами

### 1. Подключение по SSH
Выполняем команду для подключения к Raspberry Pi:

```bash
ssh user@192.168.129.150
```

Вводим пароль: `123`

После успешного входа получаем доступ к консоли Raspberry Pi.

### 2. Создание каталогов
В корневом каталоге находим каталог, соответствующий номеру группы. Внутри него создаём каталог с именем своей фамилии.

Пример команды (предположим, номер группы — `05-123`, фамилия — `Ivanov`):

```bash
cd /
ls                     # посмотреть список каталогов
cd 05-123              # перейти в каталог группы
mkdir Ivanov           # создать каталог по фамилии
```

### 3. Создание файлов и вложенных каталогов
Переходим в созданный каталог и выполняем задание преподавателя по созданию файлов и подкаталогов (например):

```bash
cd Ivanov
mkdir docs projects
touch file1.txt file2.txt
echo "Hello" > readme.md
```

### 4. Скриншот с рекурсивным списком
Выполняем команду для отображения всех каталогов и файлов рекурсивно:

```bash
ls -R
```


### 5. Завершение SSH-сессии
Выходим из подключения:

```bash
exit
```

## Часть 2. Настройка SSH-ключей для беспарольного доступа

### Назначение
SSH-ключи позволяют подключаться к Raspberry Pi без ввода пароля. Это удобнее и безопаснее при частых сеансах.

### 1. Проверка существующих ключей на ПК
Выполняем команду в терминале **вашего компьютера** (не на Raspberry):

```bash
ls ~/.ssh
```

Если есть файлы `id_rsa.pub` или `id_dsa.pub` — ключи уже созданы. Если нет — переходим к генерации.

### 2. Генерация новой пары ключей
Создаём ключи командой:

```bash
ssh-keygen
```

- На запрос пути сохранения (`Enter file in which to save the key (~/.ssh/id_rsa):`) — нажимаем `Enter` (оставляем по умолчанию).
- На запрос пароля (`Enter passphrase`) — можно нажать `Enter` дважды (оставить без пароля) или придумать пароль для дополнительной защиты.

После генерации в папке `~/.ssh` появятся два файла:
- `id_rsa` — **приватный** ключ (остаётся на ПК)
- `id_rsa.pub` — **публичный** ключ (копируется на Raspberry)

### 3. Копирование публичного ключа на Raspberry Pi
Используем команду:

```bash
ssh-copy-id user@192.168.129.150
```

Замените `user` на реальное имя пользователя (например, `pi` или `user`). Пароль (`123`) потребуется ввести один раз при копировании.

Если команда `ssh-copy-id` недоступна (например, на Windows), можно скопировать ключ вручную:

```bash
cat ~/.ssh/id_rsa.pub | ssh user@192.168.129.150 "mkdir -p ~/.ssh && cat >> ~/.ssh/authorized_keys"
```

### 4. Проверка беспарольного подключения
Теперь подключаемся без ввода пароля:

```bash
ssh user@192.168.129.150
```

Система не должна запрашивать пароль.

### 5. Завершение
При необходимости выйти из сессии:

```bash
exit
```

## Контрольные вопросы
1. Для чего нужен протокол SSH?
2. Чем отличается публичный ключ от приватного?
3. Какой файл на Raspberry хранит список разрешённых ключей?
4. Что произойдёт, если удалить файл `authorized_keys`?

Конечно. Вот **ответы на контрольные вопросы** к лабораторной работе по SSH:

---

### 1. Для чего нужен протокол SSH?

**SSH (Secure Shell)** — это сетевой протокол для удалённого управления устройствами и передачи данных в зашифрованном виде.

**Основные用途:**
- Безопасное подключение к командной оболочке (консоли) удалённого устройства (Raspberry Pi, сервер).
- Защищённая передача файлов (SFTP, SCP).
- Туннелирование (проброс портов) других протоколов.
- Выполнение команд на удалённом устройстве.

> Главное отличие от Telnet — **все данные шифруются**, включая логин, пароль и команды.

---

### 2. Чем отличается публичный ключ от приватного?

| | **Приватный (закрытый) ключ** (`id_rsa`) | **Публичный (открытый) ключ** (`id_rsa.pub`) |
|---|---|---|
| **Где хранится** | Только на вашем ПК (клиенте) | На удалённом устройстве (Raspberry Pi, сервер) |
| **Можно ли передавать** | Нет, хранится в секрете | Да, его можно копировать на сервера |
| **Для чего нужен** | Подписывает запросы и расшифровывает данные | Проверяет подпись и шифрует данные для приватного ключа |
| **Расширение файла** | `id_rsa` (без расширения) | `id_rsa.pub` |
| **Содержимое** | Начинается с `-----BEGIN OPENSSH PRIVATE KEY-----` | Начинается с `ssh-rsa AAAAB3...` |

**Аналогия для запоминания:**  
Приватный ключ — это ваш личный ключ от квартиры (никому не даёте). Публичный ключ — это замок, который вы повесили на дверь Raspberry Pi. Совпасть может только ваша связка ключа и замка.

---

### 3. Какой файл на Raspberry хранит список разрешённых ключей?

```
~/.ssh/authorized_keys
```

- Это текстовый файл, в котором каждая строка содержит один публичный ключ (обычно в формате `ssh-rsa AAA...`).
- Когда вы подключаетесь по SSH, система Raspberry сравнивает ваш приватный ключ с теми, что перечислены в этом файле.
- Если ключ найден и совпадает — доступ разрешается (пароль не требуется).

> Вы можете добавить несколько публичных ключей (например, со своего ПК и ноутбука) — все они будут иметь доступ.

---

### 4. Что произойдёт, если удалить файл `authorized_keys`?

**Последствия:**

1. **Беспарольный вход по SSH-ключам перестанет работать** — даже если ваши ключи были добавлены ранее.
2. В зависимости от настроек SSH-сервера (`/etc/ssh/sshd_config`):
   - **Если разрешена аутентификация по паролю** (`PasswordAuthentication yes`) — вы сможете войти, введя пароль (`123`).
   - **Если отключена аутентификация по паролю** (`PasswordAuthentication no`) — вы **потеряете доступ** к Raspberry Pi через SSH полностью (пока не восстановите файл через консоль или другой способ).
3. Вы можете восстановить файл:
   - Вручную: `nano ~/.ssh/authorized_keys` и вставить свой публичный ключ.
   - Снова запустить `ssh-copy-id user@ip` с вашего ПК.
